ERROR #1: SMOTE DATA LEAKAGE IN FEATURE SELECTION
──────────────────────────────────────────────────
PROBLEM:
- Feature selection was being done AFTER applying SMOTE
- SMOTE creates synthetic data points from original training data
- Selecting features from synthetic data biases the selection
- This causes the model to learn patterns from artificial data

ORIGINAL CODE (WRONG):
```python
# Applied SMOTE BEFORE feature selection
if is_imbalanced:
    smote = SMOTE(random_state=42, k_neighbors=5)
    X_train_bal, y_train_bal = smote.fit_resample(X_train, y_train)
    # Feature selection happened on X_train_bal (synthetic data!)
    
# Then feature selection on SMOTE data
mi_scores = mutual_info_classif(X_train_bal, y_train_bal, random_state=42)
```

WHY THIS IS WRONG:
- Feature selection sees synthetic patterns created by SMOTE
- Selected features are biased toward SMOTE artifacts
- Real predictive features might be missed
- Model learns to predict synthetic data, not real patterns

IMPACT: Inflated accuracy, poor generalization


ERROR #2: NO TRAIN ACCURACY REPORTING
──────────────────────────────────────
PROBLEM:
- Only test accuracy was reported
- Could not detect overfitting
- Train accuracy = 100%, Test accuracy = 100% → data leakage!
- Train accuracy = 100%, Test accuracy = 60% → overfitting!
- Without train accuracy, impossible to diagnose issues

ORIGINAL CODE (WRONG):

- Standard ML practice requires both train and test metrics

ERROR #5: FEATURE SELECTION ON WRONG DATA
──────────────────────────────────────────
PROBLEM:
- Features selected after class balancing (SMOTE)
- Should select before SMOTE to avoid bias
- Selected features influenced by synthetic data

CORRECT ORDER:
1. Split train/test (stratified)
2. Feature selection on ORIGINAL training data
3. Apply SMOTE on SELECTED features only
4. Train models
5. Evaluate on test set

WRONG ORDER (ORIGINAL):
1. Split train/test
2. Apply SMOTE on ALL features
3. Feature selection on SMOTE data  ← WRONG!
4. Train models
5. Evaluate on test set

IMPACT: Biased feature selection, inflated importance scores

Step 4: Root Cause Analysis
────────────────────────────
Why does this happen?

HYPOTHESIS 1: Survey Design
- Depression questions only asked at specific postpartum times
- Women 0-9 months postpartum: No depression survey
- Women 10-12 months postpartum: Depression survey conducted
- MTH22 captures WHEN survey was done, not depression risk

HYPOTHESIS 2: Data Merging Artifact
- Different survey waves merged together
- Wave 1: No mental health questions (MTH22 = 0-9)
- Wave 2: Mental health questions added (MTH22 = 10+)
- MTH22 distinguishes survey waves, not individual risk

HYPOTHESIS 3: Sampling Bias
- Depressed women more likely to attend 10-12 month follow-up
- Non-depressed women drop out earlier
- MTH22 captures retention bias, not true depression

ALL THREE create artificial perfect separation!

Step 5: Verification
────────────────────────

- MTH22: "Months since last birth" (DHS standard variable)
- MTH24: "Months since second last birth"
- These are timing variables, not risk factors

Medical literature review:
- Postpartum depression peaks 6-12 weeks after birth
- NO medical reason for 0% depression at 0-9 months
- The pattern is artificial, not biological
